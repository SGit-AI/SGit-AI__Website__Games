The three permissions that decide everything downstream

{ "permissions": { "append": { "write": true }, "network": true, "llm": { "chat": true } } }
  • network: true exists because the vault host's app frame ships connect-src blob: data:, so a direct fetch to the telemetry API is blocked without it (v0.12.3).
  • append.write is the bridge fallback, sg.append.write.
  • llm.chat is the chat panel from v0.14.0 — the model runs in the host and the vault's key never enters the frame. This is the constraint that decides §3.

Telemetry: two lanes on vault kqngdecz — anonymous counters and deliberate feedback kept apart so retention can differ and one cannot flood the other. RSA-OAEP-SHA256 wrapping AES-256-GCM; flush every 4 s, at most 40 flushes and 50 events per flush per session. Both tokens are write-only and blind.

Drift to note: the existing sgit.ai vault page describes v0.8.1. The vault is at v0.16.1 — roughly nine releases, including the picker, synthetic users, the results redesign, the chat panel and the whole ideas graph. §2

games.sgit.ai — the concept site

The one question this domain takes further than a section could: a game is the only artefact that makes somebody state a belief before they are told the answer — which is the only way to measure what they actually think.

Everything else we publish can be nodded at. A player of What Can It Do? has to commit to can it? before the board stamps it, and the delta between the two is data that could not have been collected another way. That claim is falsifiable: if play data shows players are as well calibrated as they think, the game measured nothing worth measuring.

Second claim, and the one the network cares about: the mandate is a by-product. Forty answers to do you want it to? and a player walks away holding a draft mandate they did not set out to write. That is the RiskMandate.ai idea — grant versus mandate, and the delta nothing covers — arrived at by playing rather than by filling in a form.

The maturity ladder

Games will sit at different maturities, so a label needs a test behind it rather than a mood.

RungMeansThe test that moves it up
sketchan idea and a rules table, nothing playable—
playableyou can finish a runa stranger finished it without being told how
scoredthe scoring is a stated rule, self-testedselftest.json passes and the rule is published
measuredplay data exists and has changed somethinga release whose notes cite play data
answeredplayers argue with it and get answers backpositions published in the ideas graph
A claim about your work, made from outside

Against that ladder today, What Can It Do? reads as scored, one release short of measured: it has telemetry and an ideas graph, but I found no release note yet saying “we changed X because the data said Y”. v0.16.1 changes the feedback UI on a bias argument — close, but that is reasoning, not data. If a release did move on play data, name it and the rung moves.

§3

The embed — the decision that needs a verdict

The network has two working embed hosts. They are not equivalent, and the difference lands squarely on features shipped in the last four releases.

Option A · recommended for the player site

The official SG/Vault UI, over the embed protocol

Loads the vault UI in an iframe, waits for vault-embed-ready, then posts vault-open with the key and a pinned targetOrigin. The key never appears in a URL and is never written to the frame's storage.

+The real host: sg.llm.chat works, so the chat panel works
+sg.append.write works, so the telemetry fallback works
+app.json permissions are read and honoured
−Vault chrome, two stacked surfaces, slower first paint
!Needs one change: the component always adds the vault-browser surface. A player site wants App Mode alone — a data-browser="0" flag, two lines
Option B · for catalogue previews

The minimal host

~170 lines: derive the ref id with HMAC-SHA256, fetch ciphertext over CORS, decrypt with Web Crypto, boot the app into a srcdoc iframe with sandbox="allow-scripts".

+Clean, fast, no chrome; cannot write by construction
−Reads only — no sg.llm.*, so the chat panel would be dead
−Ignores app.json, so permission declarations are inert
!Telemetry would fall back to direct fetch — which should work on a Pages origin with no restrictive CSP, inverting v0.12.3. Worth testing before anyone relies on it
Option C · everywhere, as well

Link out to the vault UI

Open dev.vault.sgraph.ai/#<key> in a new tab. Zero risk, zero embedding — and the sgit.ai page already recommends it, because the board has far more room in its own tab.

+Full-width board, full host, nothing to maintain
−A click and a context switch before anyone plays

Recommendation. The player site takes Option A with the app-only flag: it is the one place where trading five releases of features for less chrome would be wrong, and a dedicated domain lets App Mode run full-bleed so most of the chrome cost disappears. games.sgit.ai takes Option B for small inline catalogue previews — a card that cannot chat is fine — and Option C everywhere.

Two open items on the embed

Which credential do we publish? sgit.ai publishes f94c8b1d…e111118:4evnlwrj (64 hex — it works; it is what I read the vault with). The link in the request is t6u4ev…zpgb5:4evnlwrj, a 24-character form I have not seen documented. Same vault, different shape. If the short one is newer or rotated, the sgit.ai page needs updating too.

Both are elided above, and the short one deliberately: on shape alone it matches the documented vault key form, <passphrase>:<vault-id> — the one sgit init prints with “saved to a password manager. Not printed here, not ever.” A read key on this network is 64 hex, optionally sgit_rk1_-prefixed. Until somebody confirms which it is, it is treated as sensitive — and if it is a vault key, rotate it.

An embed is a fourth surface. Events already carry vault-app / web / local. Play from a public domain is play by strangers; play from the vault host is mostly us — and under Option A the hostname inside the frame is the vault host's, so the existing detection cannot separate them. Mechanism is your call; the ask is that the two are distinguishable.

§4

The disclosure moves with the game

The vault carries a notice with a pause switch on every page, and telemetry.html behind it. Putting the game on a public domain does not discharge that obligation; it extends it. The sgit.ai page already names this: two of four pages once said “nothing sent” while events were being sent, and it was called out precisely because the vault's subject is informed consent.

So on the player site the notice sits on the front page, visible without scrolling — not in a footer — and the pause switch works before the first question. A site about whether you know what your agent can do cannot be coy about what it is doing.

Your call

If the in-frame notice is sufficient and duplicating it outside is worse — two switches, one of which does nothing — say so. That is a real design question and you have thought about it longer than we have.

§5

Build and release — the house pattern, unchanged

Both sites follow the pattern pki, graphs and wardley-maps share. No invention: copying it is the point, because it is what stops these sites drifting.

  • Hand-written static HTML, programmatically injected chrome. admin/build/chrome.py is the single definition of nav, footer, favicon and version badge, rewritten in place across the tree.
  • admin/build/version.txt owns the version; every page carries the badge and CI enforces that they agree.
  • admin/build/validate.js is the gate — version agreement, every internal link resolves, every canonical matches CNAME, and the key-leak tripwire.
  • CI: validate → tag → deploy on push to dev; pull requests validate only. Every push is a minor release, tagged, with the version in the commit subject.
  • .md twin of every page, plus llms.txt, llms-full.txt, sitemap.xml.

The tripwire is load-bearing here, because these two sites publish a read key on purpose — it is what keeps a vault key from following it, and the published read key gets allow-listed explicitly, the way sgit.ai allow-lists its demo vaults. Two site-specific checks join it: every page with an embed must also carry the telemetry notice (mechanically, exactly the failure recorded in that sgit.ai finding), and every catalogue card's maturity label must be one of the five rungs, so a card cannot invent a status.

§6

Deliberately not doing

Not thisBecause
Forking the game into the repos The game lives in the vault; the sites embed it. Two copies drift within a week, and “no copy of the app exists on sgit.ai” is a claim the network makes and should keep making.
A second telemetry lane These sites send nothing of their own. Everything measured is measured by the game, on the lanes it already has.
Writing game content or questions Yours. If a site needs a phrase put differently, that is a request to you, not an edit by us.
Rewriting the sgit.ai vault page Beyond adding two outbound links — though it describes v0.8.1 and should be refreshed.

One precedent worth stating once on games.sgit.ai: this is the family's first fourth-level domain and its first site whose primary audience is not a practitioner. The rule that produced it — a game gets its own domain when it is meant to be shared, and the domain is the game's name so the link explains itself — is what the next game inherits.

§8

Questions for review

  1. Is §1 wrong anywhere? I read your vault instead of asking you; I would rather be corrected than accurate by luck.
  2. Option A for the player site — agreed? It costs chrome and buys the chat panel and a working append lane. If you would rather have the clean minimal frame and lose sg.llm.chat on that domain, say so and the plan changes.
  3. Which credential do we publish? The 64-hex key, the 24-character one, or both?
  4. Surface labelling — do you want to detect the embed, or should the host tell you?
  5. The maturity ladder — are the five rungs right, and is What Can It Do? at scored or already at measured?
  6. The disclosure — a notice outside the frame as well as inside, or would two pause switches be worse than one?
  7. Does the player site oversell? “Do you know what your agent can actually do?” is a sharper claim than “we measure your calibration against a published profile, which is the weakest tier there is”. Your own does-not-prove list is unusually honest and a landing page should not undo it. Where is the line?
  8. RiskMandate.ai — the mandate draft the game hands a player is the same object RiskMandate.ai is about. Should games.sgit.ai say where that goes next, or is that ahead of what exists?
